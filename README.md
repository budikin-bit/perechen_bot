# Навигатор перечневых мероприятий 2026/27 (бот для МАХ)

## Состав
| Файл | Назначение |
|---|---|
| `bot.py` | бот (long polling), SQLite для избранного |
| `common.py` | общие функции: нормализация, стемминг, организаторы, id |
| `orders.py` | чтение приказов: .rtf (предпочтительно) и .docx, реквизиты приказа |
| `parse_minobr.py`, `parse_minpros.py` | приказ → JSON (`minobr_official.json`, `minpros_official.json`) |
| `image_text.json` | текст картинок в названиях (иероглифы, «Space-π» и т.п.), ключ — sha1 картинки |
| `build_catalog.py` | сборка `catalog.official.json` (или `--variant projects`) + `catalog.report.txt` |
| `aliases.json` | псевдонимы организаторов (ВШЭ, Физтех, СПбГУ…) |
| `overrides.json` | ручные правки предметов/интересов/типа и пары «одно мероприятие в двух перечнях» |
| `diff_catalogs.py` | сравнение каталогов (проект ↔ утверждённый), влияние на избранное |
| `tests/` | pytest-тесты |

## Обновление каталога
Берите приказы в **RTF** (из справочной системы): при конвертации в docx теряются
картинки в названиях. Бот читает RTF сам, LibreOffice не нужен.
```bash
pip install -r requirements-tools.txt
python parse_minobr.py  orders_src/prikaz_521_minobr.rtf      # → minobr_official.json
python parse_minpros.py orders_src/prikaz_598_minpros.rtf      # → minpros_official.json
python build_catalog.py --report            # → catalog.official.json (+ сверка с catalog.projects.json)
python diff_catalogs.py --favs data/navigator.db               # или --favs favorites.json
```
* Без `--variant` сборка берёт утверждённые приказы, если есть **оба** `minobr_official.json` и
  `minpros_official.json`; если есть только один — останавливается с ошибкой; если нет ни одного —
  собирает по проектам и сообщает об этом.
* Откройте `catalog.report.txt`: замечания к данным приказов, доля записей без предмета/псевдонимов,
  типы, предметы, перенесённые/переименованные/пропавшие мероприятия.
* «картинка без расшифровки в строке N (sha1 …)» — в названии есть картинка, текста которой нет в
  `image_text.json`: добавьте его туда по ключу sha1 и перезапустите парсер.
* Откройте `in_both_candidates.txt`: если пара — одно мероприятие, добавьте её в
  `overrides.json → same_event`.
* Неверный предмет — правьте в `overrides.json → by_name` (ключ — название; оно нормализуется
  `common.norm_name`, так что кавычки и регистр не важны). Ключи и пары, которые ни к чему не
  применились, печатаются при сборке и попадают в отчёт.
* Идентификаторы зависят только от названия (`mo-`/`mp-` + md5 нормализованного названия). Дубли
  названий внутри одного перечня получают суффикс от организатора и номера — не от порядка строк.
* Перенос избранного: старые id, которых нет в новом каталоге, записываются в `old_ids` нового
  мероприятия, и бот переносит избранное. Сначала — точное совпадение названия (в том числе при
  переезде между перечнями Минобрнауки ↔ Минпросвещения и для старых id с суффиксом `-2`), затем
  нечёткое: латиница/кириллица и римские цифры (XIX/ХIХ), формы собственности (ФГБОУ ВО ↔
  «Федеральное государственное бюджетное…»), аббревиатуры (ВСО, КИПУ). Пары, отличающиеся
  предметом («… по физике» / «… по химии»), не сопоставляются никогда. Сопоставления с оценкой
  < 0.95 сборка печатает — проверьте их глазами. Пропавшие мероприятия перечислены в отчёте.
* `diff_catalogs.py --favs` показывает, сколько избранного сохранится (тот же id, `old_ids`,
  `legacy_key`) и что потеряется.

## Запуск бота
```bash
cp .env.example .env     # вписать MAX_BOT_TOKEN
pip install -r requirements.txt
python bot.py
```
При первом запуске `favorites.json` (если был) переносится в `navigator.db`,
старые id избранного автоматически сопоставляются с новыми.

## Хостинг (bothost.ru и подобные)
База (`navigator.db`: избранное, пользователи, статистика) и кэш сертификатов лежат в `/app/data`, если такая
папка есть: она не входит в синхронизацию с Git и переживает обновления и перезапуски. Иначе — рядом с `bot.py`.
Переопределить: `DATA_DIR` (относительный путь считается от папки `bot.py`, не от текущей папки).
`DB_PATH` задаёт только **имя** файла: база всегда лежит в `DATA_DIR`; если `DB_PATH` указывает на другую
папку, в журнале будет предупреждение. Папку `data/` не коммитьте, делайте её копии.
В журнале при запуске строка `База данных: <путь>` показывает, где лежит файл.
Если в `DATA_DIR` базы ещё нет, бот разово переносит старую, проверяя по порядку: `DB_PATH` как задан,
`<папка bot.py>/<имя>`, `<текущая папка>/<имя>`, затем `navigator.db` в этих двух папках
(журнал WAL перед копированием сливается в основной файл).

## Что полезно знать
* Номера мероприятий — настоящие, из приказа (Минобр 1…60; Минпрос 1.1…6.979). Номер 6.95 в приказе
  занят двумя разными мероприятиями — они остаются двумя записями.
* В приказе № 598 у 6.345 уровень обрезан до «Не» — принят «Не установлен» (есть предупреждение).
* Уровни: Высший, I–IV, Не установлен. Фильтр «Раздел приказа» — по шести разделам Минпросвещения.
* Если в документе нет колонки номеров (проект перечня), `6.N` присваиваются по порядку.
* `/stats [дней]` (1…365, по умолчанию 30) — анонимная статистика: популярные запросы, запросы без результата,
  популярные фильтры, избранное. Доступна только user_id из `ADMIN_IDS` в `.env`; в меню команд её нет.
  В группе статистика не публикуется: бот присылает её админу в личный чат, а в группе пишет короткую заметку.
  Свой user_id покажет команда `/myid` (работает у всех, ничего не раскрывает).
* Таблица `qlog` в `navigator.db` — анонимный лог запросов (без user_id). Запросы хранятся нормализованными
  (нижний регистр, одиночные пробелы); запросы без букв и цифр («!!!», эмодзи) не ищутся и не пишутся.
  **Хранение — 90 дней**: более старые записи удаляются при каждом запуске бота (`QLOG_KEEP_DAYS` в `bot.py`). Телефоны и e-mail в тексте запросов заменяются на «<номер>» и «<email>».
  `SELECT q, COUNT(*) FROM qlog WHERE n=0 GROUP BY q ORDER BY 2 DESC` — чего ищут и не находят.
* Обновления обрабатываются параллельно (`WORKERS`), но у каждого пользователя — строго по очереди поступления.
  При остановке (Ctrl+C) бот до 15 с дообрабатывает уже полученные обновления.
* Ожидание ввода («Введите запрос…») привязано к чату, где его открыли: в группах бот реагирует на обычный
  текст только после такого запроса в этой же группе.
* Списки результатов живут в памяти и привязаны к пользователю: после перезапуска или у другого пользователя
  кнопки старого списка сообщают, что он устарел (карточки и избранное работают).
